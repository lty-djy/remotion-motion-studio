## TSX 导入改按「够位置就并轨」（不再每个组件一行）

- 现象：导入带 `MOTION_TIMELINE` 的 TSX，原逻辑 `trackOrder: presetIndex + 1` + `laneId = 实例 id`，每个预设各占一条轨道（如 9 个预设 → 9 行）；追加导入同样用 `appendTrackOrder = min(所有轨道序号) - 1` 每次新开一条。
- 新增 `local-timeline-logic.ts` 的 `packClipsIntoReusableLanes({incoming, existing, isReusableLane, createLaneId, newLaneBaseOrder})`：按开始帧逐个分配，优先并入既有同类轨道未被占用的时间区间（最贴合间隙优先，同间隙取层级靠上的轨道），全部被占才新建轨道；本轮新建的轨道可被后续片段复用。只改 `laneId` / `trackOrder`，不动时间、不移动既有片段。
- `local-main-v2.tsx` 接线：`applyModule` 内新增 `packImportedInstances`；替换导入（读 `MOTION_TIMELINE`）用 `existing: []`，追加导入（`导入到时间轴`、代码模板）在 `setInstances(current => ...)` 内以 `current` 为既有片段合轨；字幕语义动画轨（`sourceIntentId === SRT_CAPTION_TRACK_ID`）不参与承接。追加路径原来的 `preventLaneOverlaps([...current, ...appended])` 已移除（合轨后不会重叠，避免顺移既有片段），`appendTrackOrder` 选项随之删除。
- 新建轨道序号用 `laneOrderBaseRef`（渲染期同步的最小轨道序号）预留 `incoming.length` 个位置向上取号，避免 `applyModule` 只依赖 `fps` 的闭包读到旧状态撞号。
- 验证：`scripts/test-import-lane-packing.mjs`（esbuild 编译后跑纯逻辑）覆盖串行预设合轨（9 预设 → 2 轨，仅 431-481/476-536 冲突）、真冲突仍分轨、追加并入既有空窗、不改动入参。`npm.cmd run build` 通过；`http://127.0.0.1:41735/` 返回 200，两个改动模块经 dev server 编译无错。
- 遗留：手动点效果库添加（`addInstance`）仍是每次新开独立轨道（原注释即如此声明）；尚未在真实浏览器里点过导入按钮。
