### 交付

### 关键设计决策
1. **AI 输出 manifest JSON，不写 TSX**：用户原话"AI 只做编排不写代码"。manifest-to-tsx 是确定性脚本，零猜测空间。
2. **TSX 内联 effects/* 源码**：工作台安全校验（`local-vite.config.ts` line 651-680）拒绝除 react/remotion 之外的 import。解决方案是把 effects/use-raf-progress.ts + LegacyMetricEffects.tsx + ChapterBar.tsx 三份源码 strip 一下（去 import、保留 type alias、把 `export const XEffectDef` 行清掉），再 IIFE 包起来，最后喂给 manifest-to-tsx。
3. **Board = 信息板容器**：`一段口播 = 一个 board`，板决定 palette/density/rhythm/anchor/backgroundOpacity；卡片是板内元素。这是用户原话"整体感来自容器，不来自对齐"的落地。
4. **三向数据对账**：registry-meta.mjs（技术）+ arranger-overlay.json（语义）+ registry（工作台事实）三方对账。卡片清单 = 自动生成；改动只需改源 + 重跑生成器。
5. **示例 manifest 通过率**：cyan/amber/violet/lime 4 个 accent，相邻 Board 主调不同，调色板去重 ≤ 4，每 Board 卡片数符合 density 上限。

### 不在本次改动
- **没有改工作台代码**：用户最终选择"AI 输出 JSON → 工作台原 import-to-studio 接受 TSX → 用户拖布局"。工作台 import 接口零改动。
- **没有改 registry.ts / effects/***：registry 真实可用卡仍为 14 metric + ChapterBar。chart/text/media/structure/tech/spatial/brand 等 7 大类目前空架子，留着 SKILL 给扩展口子。
- **"导入 json 改成导入 SRT"**：只在 Skill 编排层入参从 JSON 切到 SRT；工作台导入面板 / `import-to-studio.ps1` 仍接受 TSX（即 manifest-to-tsx 编译产物）。

### 当日追加 4：竖屏 9:16 卡片过小修复
用户反馈竖屏下拉满滑块卡片仍很小，横屏正常。根因：`getRegisteredEffectPosition` 竖屏非 top 分支写死 `scale=0.45`，而 metric 卡设计宽 700px → 315px 只占 1080 画布 29%；横屏走 `defaultPosition`（scale=1，占 1920 的 36%）故正常。修复：
- 竖屏非 top 卡改为按画布宽自适应：`scale = 1080 * 0.88 / bounds.width`（≈1.357，占画布 88% 宽），x 水平居中，y 逻辑不变。
- SRT 生成器复用同一函数，重新"生成时间轴"即应用新尺寸；已存在旧实例的 scale 不变（重新生成覆盖）。
- 滑块范围 50%–150% → 50%–200%，localStorage 校验同步放宽到 2.0。
- 验证：tsc 无新增错误，Vite 热更新输出确认 `.88` 与 `max: "200"` 已生效。

### 当日追加 7：修复轨道上下层关系（local-main-v2.tsx）
用户反馈看不到效果，轨道层序疑似搞反。确认是 `StudioPreviewComposition` 中 `orderedLayers` 的排序方向问题：
- 时间轴列表按 `trackOrder` 升序渲染，轨道列表最上方对应 `trackOrder` 最小。
- 原 `orderedLayers.sort((a,b)=>a.order-b.order)` 让列表最上方先渲染、沉在底层，视频轨道（位于列表底部）反而覆盖在最上层，导致动效被视频遮住。
- 改为 `sort((a,b)=>b.order-a.order)`：列表最上方轨道后渲染、在顶层；列表最下方（视频）先渲染、在底层。
- 验证：tsc 无新增错误；Vite 已服务新排序代码。
