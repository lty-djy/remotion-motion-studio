# 我的偏好（取值表 · 中性默认）

> **这份是出厂默认值，故意是中性的。** 它不代表任何人的审美，只保证生成出来的编排
> 「结构正确、不出错」——但它**不会**替你做风格决定。
>
> **风格是你自己长出来的，不是随包附赠的。** 用法：
>
> 1. 按默认值先排一期，导入工作台预览、微调、确认插入；
> 2. 在工作台里按你自己的想法改（改落位、改密度、改颜色、删你不喜欢的卡）；
> 3. 改完后对 AI 说一句 **「学一下」** —— 它会对比「AI 排的」和「你改完的」，
>    把出现两次以上的倾向问你确认，写进同目录的 `我的偏好.md` 和 `经验规则.md`；
>    工作台确认插入时也会自动累计组件偏好分（`public/input/arrangement-rules/rule-manifest.json` 的 `componentScores`），开工时先读它。
> 4. 下一期就按你的取值排。三五期之后，这份表里的数字全是你的。
>
> **不要直接改这个文件**（升级会覆盖）。改动一律写进同目录 `我的偏好.md`，
> 同名条目覆盖这里 —— 和 `lint-rules.default.json` / `lint-rules.local.json` 一个道理。

## 密度与节奏

| 条目 | 默认值 | 说明 |
|---|---|---|
| 密度区间 | **8–12 张/分钟** | 中性起点。想更紧凑就往上调，想留白多就往下调 |
| 新动作间隔 | **2–4 秒** | 一个「新动作」= 新卡进场，或卡内下一条弹出（`riskIntervalSeconds`/`stepEnterIntervalSeconds` 这类逐条参数推进一步也算） |
| 留白上限 | **不设** | 叙述过渡段可以什么都不放 |
| 短卡时长 | **3–5s** | 一句话的信息卡 |
| 内容卡时长 | **5–12s** | 跟着讲述时长走，不套固定值 |
| 常驻卡时长 | **跟整期（0 → 视频结尾）** | ChapterBar、字幕轨 |
| 爆点卡 | **不设上下限** | 你自己判断哪里该炸 |
| 论点卡陪跑 | **跟整段走** | 一个论点配一张主卡，活多久由这段话讲多久决定 |

## 多样性

| 条目 | 默认值 | 说明 |
|---|---|---|
| 相邻两张卡不同 componentId | **是** | 防呆硬规则 |
| 全片组件种类数下限 | **不设**（lint 默认查 ≥6） | 偏好表写「不设」就真的不设 |
| 同种卡重复上限 | **不设**（lint 默认 ≤4） | |
| 同屏叠卡上限 | **2 张** | 工作台卡面普遍较大，超过 2 张容易糊；可读性下限 |
| 同屏进场错开 | **≥0.5s** | 同时炸出会看不清，可读性下限 |

## 落位

| 条目 | 默认值 | 说明 |
|---|---|---|
| 主轴 | **不锁死** | 只要求避开画面中央的人物。要不要「所有卡都排左列」是你的风格选择 |
| position 分配 | **用组件目录默认落位** | 不发明像素坐标；哪类内容固定放哪儿由你在 `我的偏好.md` 里定 |
| 双列对照 | **右列按画布宽度的 60% 起算** | 1080 竖屏约 x=648 |

## 颜色

| 条目 | 默认值 | 说明 |
|---|---|---|
| JSON 里写颜色 props | **不写** | 组件自带配色 + 工作台「主色/保持一致」开关管颜色；用户点单指定颜色时才在 JSON 里填 |
| 色义约定 | **不预设** | 「蓝=数据、红=否定」这类映射是你的设计约定，定好后写进 `我的偏好.md` |
| 一段一色 | **是** | 同段卡片强调色一致；分段换色用工作台主色开关，不靠 JSON |
| 整期主色 | **由你定** | 工作台编排弹窗里选；不方便定就保持组件默认 |

## 文字量

| 条目 | 默认值 | 说明 |
|---|---|---|
| 卡面文字 | **必须短于口播原句** | 硬约束：禁止把 SRT 原句整句搬上卡。**具体几个字由你定** |
| 条目字数上限 | **不设** | |
| 标题字数上限 | **不设** | |
| 纯文字卡占比 | **不设** | 图形优先是默认方向，见 SKILL.md |
| 英文小标签（eyebrow） | **可选** | 要不要配、什么风格，是风格选择 |

## 常驻层

| 条目 | 默认值 | 说明 |
|---|---|---|
| `ChapterBar` 章节条 | **可选** | 长视频（>3 分钟）或章节结构明显时建议配 |
| `SrtSemanticCaptions` 字幕轨 | **每期一条** | 配 SRT 使用；⚠️ 原片已有烧录字幕时**不要**配，会重复 |
| 章节数 | **按内容定** | 3–6 个是常见区间 |

## 结构

| 条目 | 默认值 | 说明 |
|---|---|---|
| 一段一主卡 | **建议，不强制** | 同段最多一张标志性主卡承担主画面 |
| 段落清场 | **建议** | 段落结束时同段卡片一起退场（共用 endFrame），再开始下一段的累积 |
| laneId 分轨 | **按语义段命名** | 章节条 `resident`、字幕 `caption`、内容 `semantic`、音效 `sfx` 是默认分法，可改 |
| 每几段换一次景 | **不设** | 需要换景时用 `FocusCamMove` 或全屏卡 |

## 不受本表影响的（改这些会出错，不是风格问题）

这些是工程硬约束，写在 `SKILL.md` 里，**不要写进偏好表**：

- 输出格式（`motionTimeline`/`componentId`/`startFrame`/`durationInFrames`/`props`），见 `references/timeline-json.md`
- `componentId` 只能用组件目录里存在的，不许发明
- `props` 字段名只能在组件目录登记的白名单里选
- `startFrame`/`durationInFrames` 必须来自 SRT 的真实时间，不许自己编
- 卡内逐条节奏参数（`riskIntervalSeconds`/`stepEnterIntervalSeconds`/`tagEnterIntervalSeconds`…）必须用 SRT 实际时长推算
- 「先分段脚本，再配组件」这个两步流程
- 资源轨道的 `resourceId` 必须存在于 `public/input/resource-index.json`
- 人物遮挡 / 字幕遮挡确认不了就诚实写 `pending`，不编 `passed`
